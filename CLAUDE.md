# CLAUDE.md — конституция проекта gateway-universal

`gateway-universal` — шаблон для развёртывания прозрачного шлюза обхода блокировок
на Debian/Ubuntu за одну команду (нативный xray VLESS+Reality gRPC + zapret/nfqws +
iptables + Instagram QUIC bypass, без Docker). Цель и критерии — [GOALS.md](GOALS.md).
Архитектура — [docs/CANON.md](docs/CANON.md). Задачи — [TASKS.md](TASKS.md).
Решения — [DECISIONS.md](DECISIONS.md).

## Роли документов (важно)
- **README.md / AGENT.md** — пользовательская дока: как ставить, что спрашивать, troubleshooting. Для конечного пользователя и деплой-агента.
- **docs/CANON.md** — внутренняя правда об архитектуре со ссылками файл:строка. Для тимлида и исполнителей.
- **docs/STRATEGIES.md / TROUBLESHOOTING.md** — справочники по zapret и отладке.
- Архитектуру дублировать между README/AGENT и CANON нельзя — при расхождении правда в CANON, а CANON сверяется с кодом.

## Незыблемые правила
1. Истина — только исполняемое: код, конфиги, тесты. Проза — не источник истины.
2. Состояние проекта живёт в файлах репозитория, не в контексте сессий. В голове сессии нет ничего уникального.
3. Каждое утверждение о коде — со ссылкой файл:строка. Не знаешь — пиши «НЕ ПОДТВЕРЖДЕНО» и спрашивай.
4. Новые архитектурные .md не плодить. Канон — docs/CANON.md, он обновляется. Фиксация поведения = тест, не проза.
5. Данные из внешних систем (VPS, 3x-ui) не выдумывать — только реальные значения/вызовы. Нет доступа — скажи и спроси.
6. Всё в git: коммит после каждой принятой задачи, понятное сообщение. Любую правку можно откатить.

## Специфичные правила проекта (инварианты — ломать = баг)
- `iptables-save` только при остановленном zapret ([install.sh:390](install.sh:390)) — иначе NFQUEUE-правила сломают ребут.
- Meta-IP ACCEPT для QUIC ставится ПЕРЕД глобальным DROP ([zapret/zapret.sh:15](zapret/zapret.sh:15)).
- Основной канал — gRPC :2083, не Vision :443 (DECISIONS).
- Проект нативный — Docker не вводить. config.env не коммитить.
- Стратегии zapret менять только по явной задаче — они калиброваны под актуальный ТСПУ.
- Схема `gateway.db` — только в [scripts/gwdb.py](scripts/gwdb.py), gateway-ui зовёт тот же скрипт, не дублирует.
- Перед добавлением Go-зависимости с cgo/C-транспайлером — сначала `df -h /` на целевой машине (неттоп, диск 6-10ГБ ЦЕЛИКОМ). Реальный инцидент: `modernc.org/sqlite` уронил сборку в `no space left on device` (DECISIONS 2026-07-20).

## Ротация тимлида
Смерть сессии — штатное событие. TASKS.md и DECISIONS.md обновляются СРАЗУ после события,
не «в конце сессии». При ~70% контекста: довести текущую задачу до приёмки, выполнить протокол
передачи, сообщить о готовности к ротации.
**Тест здоровья:** «убей сессию сейчас — что потеряется?» Правильный ответ — ничего.

### Протокол передачи
Обновить TASKS.md и DECISIONS.md; недостающее знание дописать в существующие файлы (не в новые);
вывести 5 строк: в работе / заблокировано / следующий шаг. Хендоф-документы и пересказы запрещены.

## Работа с исполнителями
- Субагенту — минимум контекста: текст задачи + критерий приёмки + пути к файлам, без истории проекта.
- От субагента — вердикт 5–10 строк: статус, команда проверки, PASS/FAIL, пути к артефактам.
- Тимлид не читает код исполнителей и не тащит логи в свой контекст.
- Приёмка только по исполняемой проверке + демонстрация (вход → выход → команда запуска).
- Не прошло — одно конкретное замечание и новый цикл. Тимлид не чинит сам.

## Подбор модели исполнителя (экономия токенов)
- **L (лёгкая)** — механика: переименования, перенос файлов, статусы, код по шаблону, прогон тестов → дешёвая модель (Haiku).
- **M (средняя)** — типовой код по ясному ТЗ, тесты на известное поведение, рефакторинг одного модуля, разбор логов → средняя (Sonnet).
- **H (тяжёлая)** — архитектура, отладка «не знаю где ломается», задачи через несколько модулей, ревью → сильная модель.
- Сомневаешься — бери дешевле. Два провала подряд = чини постановку, не модель. Ревьюер на приёмке — не слабее исполнителя.
- В TASKS.md у каждой задачи указан уровень (L/M/H).

## Тестирование
- Новая фича = тест на неё в той же задаче.
- Найденный баг = сначала тест, воспроизводящий баг, потом фикс.
- Smoke-тест «шлюз жив»: [tests/smoke.sh](tests/smoke.sh) — один прогон, PASS/FAIL, exit 0/1 (G1–G4 + egress). Гонять после изменения доменов/конфига.
- Что машина проверить не может (видео грузится, voice работает) — чек-лист демонстраций в GOALS.md.
